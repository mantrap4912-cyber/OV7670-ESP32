# OV7670 ESP32 NonFIFO

Hardware-DMA camera driver for a **bare OV7670 with no AL422B FIFO chip**, wired
directly to an ESP32.

The pixel bus is captured by the ESP32's **I2S0 peripheral in camera (DVP) mode**,
which samples D0–D7 on the sensor's own pixel clock and pushes the result into RAM
over DMA. No `digitalRead()` loop is involved anywhere — that approach cannot work,
and the first section below explains why.

```cpp
#include <OV7670.h>

OV7670Camera camera;
OV7670Pins   pins = OV7670_PINS_DEFAULT;

void setup() {
  Serial.begin(115200);

  OV7670Config cfg;
  ov7670_config_defaults(&cfg);          // QQVGA RGB565 @ 16 MHz XCLK
  cfg.frame_size = OV7670_FRAMESIZE_QQVGA;

  if (camera.begin(pins, cfg) != ESP_OK) {
    Serial.println("camera not found");
    return;
  }

  if (camera.captureFrame()) {
    size_t len;
    uint8_t *fb = camera.getFrameBuffer(&len);
    // ... 160 x 120 x 2 bytes of RGB565 ...
    camera.releaseFrameBuffer();
  }
}
```

## Why a FIFO-less OV7670 is hard

The OV7670 has no frame buffer. It clocks out one byte per PCLK edge and forgets
it immediately — if nobody catches that byte in the same clock period, it is gone.
PCLK runs at several MHz, which is far beyond what a software polling loop on
8 GPIOs can follow. Modules that carry an AL422B FIFO sidestep this by buffering a
whole frame in the chip, letting the microcontroller read it back at its leisure.
A bare module gives you no such luxury.

The fix is to stop trying to do it in software. The classic ESP32's I2S0
peripheral has an alternate personality — camera mode — in which it becomes an
8-bit parallel sampler: PCLK drives its sample clock, HREF gates the data, and the
FIFO drains straight into RAM over DMA. **That peripheral is the FIFO**,
implemented in silicon instead of an external chip. This library wraps it.

## Supported hardware

| Target | Peripheral | Status |
|---|---|---|
| ESP32 (WROOM / WROVER, classic) | I2S0 camera mode | **Supported.** Primary target. |
| ESP32-S3 | LCD_CAM + GDMA | Experimental, opt-in, not hardware-verified. See below. |
| ESP32-S2 / C3 / C6 | — | Not supported; no compatible parallel capture peripheral in this library. |

The S3 back end is complete code but the author has not run it on real silicon,
and LCD_CAM register field names have shifted between ESP-IDF releases. It is
therefore gated behind `-DOV7670_ENABLE_LCDCAM_EXPERIMENTAL`; without that flag an
S3 build stops with an explanatory `#error` rather than silently handing you a
driver nobody has tested. If you need a proven S3 camera driver today, use
Espressif's [`esp32-camera`](https://github.com/espressif/esp32-camera). If you get
this one working, a PR saying so is very welcome.

## Installation

**Arduino IDE** — Sketch → Include Library → Add .ZIP Library, or clone into your
`Arduino/libraries/` folder. Requires the
[arduino-esp32](https://github.com/espressif/arduino-esp32) core (2.x or 3.x).

**PlatformIO** — add to `platformio.ini`:

```ini
lib_deps = https://github.com/ketan/OV7670-ESP32-NonFIFO.git
```

**ESP-IDF** — drop the directory into `components/`, or point
`EXTRA_COMPONENT_DIRS` at it, and add `ov7670_esp32_nonfifo` to your `REQUIRES`.

## Wiring

Default pin map (`OV7670_PINS_DEFAULT`, for a 38-pin ESP32 DevKit-C). Nothing in
the library depends on these; pass your own `OV7670Pins`. Full reasoning,
constraints and alternatives are in [docs/WIRING.md](docs/WIRING.md).

| OV7670 | ESP32 | Direction | Notes |
|---|---|---|---|
| 3V3 | 3V3 | — | **3.3 V only.** 5 V destroys the sensor. |
| GND | GND | — | Keep the ground return short. |
| SIOC | 27 | → sensor | SCCB clock. Needs a 4.7 kΩ pull-up to 3V3. |
| SIOD | 26 | ↔ | SCCB data. Needs a 4.7 kΩ pull-up to 3V3. |
| VSYNC | 25 | → ESP32 | Frame sync. Drives a GPIO interrupt. |
| HREF | 23 | → ESP32 | Line/data gate. Routed to the capture peripheral. |
| PCLK | 22 | → ESP32 | Pixel clock. Drives the DMA sample clock. |
| XCLK | 21 | → sensor | Clock **into** the sensor, generated by LEDC. |
| RESET | 19 | → sensor | Active low. Drive it; do not leave it floating. |
| PWDN | 18 | → sensor | Active high. Drive it; do not leave it floating. |
| D0 | 34 | → ESP32 | LSB |
| D1 | 35 | → ESP32 | |
| D2 | 32 | → ESP32 | |
| D3 | 33 | → ESP32 | |
| D4 | 4 | → ESP32 | |
| D5 | 36 | → ESP32 | input-only pin |
| D6 | 39 | → ESP32 | input-only pin |
| D7 | 13 | → ESP32 | MSB |

Keep the wires short. This is a multi-megahertz parallel bus on jumper leads;
20 cm of unshielded ribbon is already marginal. If you have flaky pixels before
you have clean ones, shorten the wiring before you touch the code.

## Resolution, format and memory

Frame buffer size is `width × height × bytes-per-pixel`. The DMA ring is separate
and must live in **internal** RAM; the frame buffer itself may be PSRAM.

| Frame size | Pixels | RGB565 / YUV422 | Grayscale | DMA ring (4 nodes) |
|---|---|---|---|---|
| QQCIF | 88 × 72 | 12.7 kB | 6.3 kB | 1.4 kB |
| QQVGA | 160 × 120 | 38.4 kB | 19.2 kB | 2.5 kB |
| QCIF | 176 × 144 | 50.7 kB | 25.3 kB | 2.8 kB |
| QVGA | 320 × 240 | 153.6 kB | 76.8 kB | 5.1 kB |
| CIF | 352 × 288 | 202.8 kB | 101.4 kB | 5.6 kB |
| VGA | 640 × 480 | **614.4 kB** | 307.2 kB | 10.2 kB |

A plain ESP32-WROOM has roughly 320 kB of usable SRAM, and never all of it in one
contiguous block once WiFi is running. In practice:

- **No PSRAM:** QQVGA and QCIF are comfortable, QVGA is usually fine, CIF is tight,
  VGA is impossible as a full frame.
- **PSRAM (WROVER-class):** everything up to VGA fits, with `cfg.use_psram = true`.
- **Any board, any resolution:** use `OV7670_CAPTURE_LINE_CALLBACK`, which
  allocates no frame buffer at all and hands you each line as it arrives. This is
  how you get VGA out of a WROOM — straight to a display or a network socket,
  never held in full.

Pixel formats: `RGB565`, `RGB555`, `RGB444`, `YUV422`, `GRAYSCALE` (extracted from
the YUV luma channel during DMA unpacking, so it costs half the memory for free)
and raw `BAYER`.

## Examples

Work through them in order. Each one is the acceptance test for a milestone, and
skipping ahead is the single most common reason these builds stall.

| Example | What it proves |
|---|---|
| **01_ChipIDTest** | SCCB and XCLK work. Reads PID/VER 100 times. **Start here.** |
| **02_StillCaptureSerial** | One QQVGA frame over DMA, dumped as base64 and decoded to a PNG on your PC. This is the milestone that proves the whole approach. |
| **03_LiveViewTFT** | Live view on an SPI TFT, showing both the full-frame and low-RAM line-callback paths. |
| **04_WiFiStreamServer** | Frames served over HTTP to a browser as BMP. |
| **05_ContinuousBenchmark** | Frame rate and RAM for every size/format combination, measured on your board. |
| **06_ImageControls** | Interactive brightness, contrast, saturation, white balance, effects, exposure and gain. |
| **07_StressTest** | Hours-long stability run: torn frames, heap leaks, stall recovery. |
| **08_CaptivePortalCam** | Self-contained access point with a DNS captive portal — join the WiFi from a phone and the camera view opens by itself. No router, no IP address to type. |

`tools/decode_frame.py` turns a serial dump into a PNG:

```
python tools/decode_frame.py frame.txt -o frame.png
```

It falls back to writing a netpbm file if Pillow is not installed, so it has no
hard dependencies.

## Configuration knobs that matter

```cpp
OV7670Config cfg;
ov7670_config_defaults(&cfg);

cfg.xclk_freq_hz    = 16000000;  // 8–24 MHz. 16 is a safe starting point.
cfg.clkrc_prescaler = 1;         // Divides the sensor's internal clock, which
                                 // slows PCLK. Raise it if capture is flaky on
                                 // long wires; drop to 0 for maximum frame rate.
cfg.dma_node_count  = 4;         // DMA ring depth in lines. More = more slack
                                 // before data is overwritten. Raise if torn.
cfg.fb_count        = 2;         // Double buffer: capture while you read.
cfg.use_psram       = true;      // Frame buffers in PSRAM when available.
cfg.i2c_port        = 0;         // -1 selects the bit-banged SCCB transport,
                                 // which tolerates sloppier bus timing.
cfg.vsync_invert    = false;     // Set these if your breakout buffers and
cfg.href_invert     = false;     // inverts the sync lines. Do not assume —
cfg.pclk_invert     = false;     // some boards genuinely do.
```

## When it does not work

[docs/TROUBLESHOOTING.md](docs/TROUBLESHOOTING.md) is organised by symptom,
including by *what the broken image looks like*. The short version, in the order
worth checking:

1. **Nothing over SCCB / PID reads 0x00.** XCLK is not running, or is started
   after the first SCCB write. The sensor has no oscillator; without XCLK it
   cannot answer. Run `01_ChipIDTest`.
2. **PID reads garbage intermittently.** Missing pull-ups on SIOC/SIOD, or the
   SCCB clock is too fast. Try `cfg.sccb_freq_hz = 50000` or `cfg.i2c_port = -1`.
3. **Capture times out.** PCLK or VSYNC is not connected, or VSYNC polarity is
   inverted on your board — try `cfg.vsync_invert = true`.
4. **Image is noise, but the colour bar is clean.** The capture path is fine;
   the sensor's register configuration or the lighting is the problem.
5. **Image tears or shears diagonally.** The DMA ring is being overwritten before
   the CPU drains it. Raise `dma_node_count`, raise `clkrc_prescaler`, or shorten
   the wires.
6. **Out of memory at VGA.** Expected on a board without PSRAM. Use
   `OV7670_CAPTURE_LINE_CALLBACK`, or a smaller frame.

## Design notes

- **XCLK before SCCB, always.** `begin()` enforces the order: drive RESET/PWDN,
  start LEDC, release reset, then talk to the sensor.
- **The 7-bit address is 0x21.** The datasheet's 0x42/0x43 are bus bytes with the
  R/W bit already appended. Passing 0x42 to `Wire` talks to nothing.
- **SCCB reads are two transactions.** The OV7670 does not support a repeated
  START for register reads; both transports here issue a full STOP in between.
- **VSYNC is handled in software.** Its polarity varies between modules, and
  feeding an active-high hardware gate with a signal that is high during blanking
  enables capture exactly when there is no data. A GPIO interrupt with a
  selectable edge sidesteps the whole class of problem.
- **Unpacking happens in a task, not an ISR.** The I2S FIFO pads each sample with
  a byte, so the DMA buffer is twice the line length and has to be squeezed. Doing
  that in a task keeps the ISRs short and lets frame buffers live in PSRAM — an
  ISR flagged `IRAM_ATTR` may run with the cache disabled and must never touch
  cached memory.

## Register table provenance

The base initialisation and per-format tables in `src/ov7670_presets.cpp` derive
from the mainline Linux driver `drivers/media/i2c/ov7670.c` (GPL-2.0), which in
turn derives from OmniVision's reference settings; the windowing values are
credited to OmniVision there. The DCW down-sampling values for QQVGA and QQCIF
follow the OV7670 Software Application Note. These are reproduced as
register/value pairs — facts about the hardware — re-expressed against this
library's own table format and symbol names. A large fraction of them are
undocumented "reserved" values that simply have to be written; resist the urge to
prune the ones without comments.

## Status and honesty about testing

This library is complete and self-consistent, and the host-side tooling is
round-trip tested. The register tables and the DMA capture path are built from
documented hardware behaviour and well-established reference settings, but the
author has **not** validated them against a physical OV7670 module. Treat the
first run as bring-up: work the examples in order, and
[open an issue](https://github.com/ketan/OV7670-ESP32-NonFIFO/issues) with what
you see if a milestone does not pass. Reports from real hardware are the most
useful contribution this project can receive right now.
